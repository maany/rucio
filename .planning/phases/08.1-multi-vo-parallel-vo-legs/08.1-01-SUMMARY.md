# Phase 08.1 Plan 01: Multi-VO Single-Leg Selector Summary

Parameterized the multi_vo test harness so a single matrix leg runs exactly one VO (tst or ts2) when `RUCIO_MULTI_VO_LEG` is set, while preserving today's sequential tst→ts2 behavior when the selector is absent; each VO leg now gets a per-VO-unique compose project name so two parallel stacks never collide.

## What Was Built

- **Task 1 — Per-VO-unique compose project name + host threading** (`3d8257150`)
  - `ContainerManager.make_project_name(suite, rdbms, vo=None)`: when `vo` is truthy returns `rucio-test-{suite}-{vo}-{rdbms}` (e.g. `rucio-test-multi_vo-ts2-postgres14`); otherwise the legacy `rucio-test-{suite}-{rdbms}`. Network name derives from project name, so the per-VO name also keeps the compose network unique per VO. `PROJECT_PREFIX` unchanged (orphan-cleanup still matches `rucio-test-`).
  - `plugin.py` host forwarding branch: computes `mv_leg = os.environ.get("RUCIO_MULTI_VO_LEG") if profile.name == "multi_vo" else None` and threads it into `make_project_name`. Non-multi_vo legs pass `vo=None` → byte-identical names.

- **Task 2 — run_multi_vo() single-VO selector + leg-aware base config** (`e8a68db56`)
  - `run_multi_vo()`: reads `leg = os.environ.get("RUCIO_MULTI_VO_LEG", "").strip()`. When `leg in {tst, ts2}` it builds one streamed cmd (`forward_stream=True`), bootstraps only that VO's home, runs one subprocess, and returns its rc. When unset it preserves the existing sequential tst→ts2 gate path exactly.
  - `_activate_multi_vo_base_config()`: leg-aware `home = HOMES.get(leg, "/opt/rucio/etc/multi_vo/tst")`, so the ts2 leg's base bring-up runs under the ts2 cfg (provisions testvo2) while defaulting to tst when unset/unrecognized. All 08-04 fixes remain in force per leg.

- **Task 3 — Unit tests** (`e648515fb`)
  - `test_run_multi_vo_single_leg_ts2_streams` / `_tst_streams`: assert exactly one subprocess, correct `RUCIO_HOME`, forwarder plugin present (streaming), correct bootstrap_vo target, rc returned.
  - Hardened `test_run_multi_vo_order_and_gate` and `test_run_multi_vo_only_tst_streams` with `delenv("RUCIO_MULTI_VO_LEG")` to exercise the sequential path deterministically.
  - `test_make_project_name_per_vo`: per-VO names plus byte-identical legacy no-vo name.
