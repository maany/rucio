Create `tests/ruciopytest/profiles.py` with:

1. **SuiteProfile frozen dataclass** with these fields:
   - `name: str` — suite name (remote_dbs, sqlite, etc.)
   - `rdbms: str` — default RDBMS backend (e.g., "postgres14", "sqlite")
   - `compose_profiles: tuple[str, ...]` — docker compose --profile values (empty tuple for sqlite)
   - `xdist_enabled: bool` — whether this RDBMS supports parallel execution
   - `default_workers_ci: int` — default xdist worker count in CI (0 for incompatible)
   - `default_workers_local: str` — default for local ("auto" or "0")
   - `test_paths: tuple[str, ...]` — test paths to include
   - `markers: tuple[str, ...]` — pytest markers to filter by
   - `env_vars: dict[str, str]` — extra environment variables (e.g., RUCIO_HOME for multi_vo)

2. **SUITE_PROFILES dict** mapping suite name to SuiteProfile for all 5 suites:
   - `remote_dbs`: rdbms=postgres14, compose_profiles=("postgres14",), xdist_enabled=True, default_workers_ci=3, default_workers_local="auto"
   - `sqlite`: rdbms=sqlite, compose_profiles=(), xdist_enabled=False, default_workers_ci=0, default_workers_local="0"
   - `multi_vo`: rdbms=postgres14, compose_profiles=("postgres14",), xdist_enabled=True, env_vars={"RUCIO_HOME": "/opt/rucio/etc/multi_vo/tst"}
   - `client`: rdbms=postgres14, compose_profiles=("client",), xdist_enabled=True
   - `votest`: rdbms=postgres14, compose_profiles=("postgres14",), xdist_enabled=True

3. **resolve_profile function**: Takes suite_name (str) and optional rdbms_override (str). Returns SuiteProfile. If rdbms_override is provided, creates a new profile with updated RDBMS and recalculated xdist_enabled (only postgres14 is xdist-compatible). Raises ValueError for unknown suite names.

  <name>Task 2: Create xdist configuration module and main plugin module</name>

  <action>
**Part A: Create `tests/ruciopytest/xdist_config.py`**

Create a module with a single public function:

`configure_xdist(config: pytest.Config, profile: SuiteProfile) -> int`:
- Guard: if `not config.pluginmanager.hasplugin("xdist")` then return 0 (xdist not installed).
- If `not profile.xdist_enabled`:
  - Check if user passed `--xdist-workers` with a value > 0. If so, emit a `warnings.warn()` saying the suite's RDBMS does not support parallel execution and the override is being ignored.
  - Set `config.option.numprocesses = 0` and `config.option.dist = "no"`. Return 0.
- If user passed `--xdist-workers=N` (not None), set `config.option.numprocesses = N`. Return N.
- Auto-detect CI: check `os.environ.get("GITHUB_ACTIONS") == "true"` or `os.environ.get("CI") == "true"`.
  - If CI: set `config.option.numprocesses = profile.default_workers_ci`. Return that value.
  - If local: leave numprocesses as-is (respect any `-n` the user may have passed). Return `getattr(config.option, 'numprocesses', 0)`.

Use stdlib only (os, warnings). Import pytest and SuiteProfile.

**Part B: Create `tests/ruciopytest/plugin.py`**

Create the main plugin module with:

1. **StashKey definitions** at module level:
   - `suite_profile_key = pytest.StashKey[SuiteProfile]()`

2. **`pytest_addoption(parser)`**: Register in a "rucio" option group:
   - `--suite`: choices=["client", "remote_dbs", "sqlite", "multi_vo", "votest"], default=None (dormant when not provided). Help text: "Test suite to run".
   - `--xdist-workers`: type=int, default=None, dest="xdist_workers". Help text: "Number of xdist workers (overrides auto-detection)".

3. **`pytest_configure(config)`**:
   - FIRST: Check `hasattr(config, 'workerinput')` — if True, this is an xdist worker. Workers should still resolve the profile (it's cheap) and store in stash, but skip xdist configuration and summary printing. This ensures workers can access the profile from stash.
   - Get `suite_name = config.getoption("suite", default=None)`. If None, return (plugin dormant).
   - Get RDBMS override from `os.environ.get("RDBMS")`.
   - Call `resolve_profile(suite_name, rdbms_override)` to get profile.
   - Store profile: `config.stash[suite_profile_key] = profile`.
   - Set `os.environ["SUITE"] = suite_name` for backward compatibility (Pitfall 4 from RESEARCH.md).
   - If NOT a worker: call `configure_xdist(config, profile)`.
   - If NOT a worker: call `_print_profile_summary(config, profile)`.

4. **`_print_profile_summary(config, profile)`** (private):
   - Get effective worker count from `getattr(config.option, 'numprocesses', 0)` (guarded for xdist not installed).
   - Print a clear box with: suite name, RDBMS, xdist enabled, worker count, test paths.
   - Use `config.get_terminal_writer()` for output (not bare print).

Include CERN copyright header. Use `from __future__ import annotations`. Keep imports minimal — stdlib + pytest + local imports from profiles and xdist_config modules only (PLUG-02 compliance).
  </action>
