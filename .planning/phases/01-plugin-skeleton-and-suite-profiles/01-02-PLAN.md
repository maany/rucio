  <name>Task 1: Register plugin and migrate --suite from conftest.py</name>
  <files>tests/conftest.py</files>
  <action>
Modify `tests/conftest.py` to integrate the new plugin:

1. **Update pytest_plugins tuple** to include the new plugin:
   ```python
   pytest_plugins = (
       'tests.ruciopytest.artifacts_plugin',
       'tests.ruciopytest.plugin',
   )
   ```

2. **Remove --suite from conftest.py's pytest_addoption**: The plugin now defines `--suite` and `--xdist-workers`. Conftest.py should ONLY keep `--activate-rses` and `--keep-db` (these are Phase 2+ options that stay in conftest.py for now). This avoids the Pitfall 1 collision described in RESEARCH.md.

3. **Update conftest.py's pytest_configure**:
   - KEEP the marker registration lines (dirty, noparallel, needs_iam, flaky) — these are conftest.py's responsibility.
   - KEEP the xdist_noparallel_scheduler registration — this existing scheduler is independent of the new plugin.
   - CHANGE the `suite = config.getoption("--suite", default=None)` line: The suite option still exists (now from plugin), so the getoption call still works. But now the plugin's pytest_configure has ALREADY run (since it's registered in pytest_plugins), so `config.stash[suite_profile_key]` is available. Import `suite_profile_key` from `tests.ruciopytest.plugin` and use it to check if a profile was resolved.
   - KEEP all existing database setup logic (purge_db, schema build, etc.) — this is Phase 2 migration scope. In this plan, we only change how the suite name is read.
   - Replace `suite = config.getoption("--suite", default=None)` with:
     ```python
     from .ruciopytest.plugin import suite_profile_key
     profile = config.stash.get(suite_profile_key, None)
     suite = profile.name if profile else config.getoption("suite", default=None)
     ```
     This way, if the plugin resolved a profile, use it. If not (plugin dormant), fall back to the option directly. This maintains backward compatibility.

4. **Verify no import-time issues**: The plugin module imports should not trigger database connections. Only import from the plugin what's needed (StashKey, not rucio internals).

IMPORTANT: Do NOT change any existing fixture definitions, factory imports, or database setup logic. Only change the option registration and how suite is resolved. The rest of conftest.py must remain identical.
