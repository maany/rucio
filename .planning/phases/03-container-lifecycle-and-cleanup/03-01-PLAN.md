  <name>Task 1: Create ContainerManager class with compose lifecycle, readiness checks, orphan cleanup, and cleanup handlers</name>
  <files>tests/ruciopytest/container_manager.py</files>
  <action>
Create `tests/ruciopytest/container_manager.py` with a `ContainerManager` class. Use only stdlib modules (subprocess, signal, atexit, json, os, pathlib). Follow the patterns from 03-RESEARCH.md.

**Class constants:**
- `COMPOSE_DIR = "etc/docker/dev"` (hardcoded per PLUG-03 locked decision)
- `COMPOSE_FILES = ("docker-compose.yml", "docker-compose.test.override.yml")` (always include both per research recommendation)
- `PROJECT_PREFIX = "rucio-test-"` (for orphan detection)
- `LOG_DIR = ".test-logs"` (for log capture, used by Plan 02)

**Constructor `__init__(self, project_name, profiles, root_dir)`:**
- `project_name`: string like `rucio-test-remote_dbs-postgres14` (SUIT-05)
- `profiles`: tuple of compose profile names from `SuiteProfile.compose_profiles`
- `root_dir`: pytest `config.rootdir` as string, used to resolve compose file paths (avoids Pitfall 5: CWD-relative paths)
- `_started = False`, `_cleaned_up = False` flags for idempotent cleanup
- `_original_sigterm = None`, `_original_sigint = None` for handler restoration

**Helper `_compose_cmd(self, *args) -> list[str]`:**
Build the full docker compose command: `["docker", "compose", "-p", self._project_name]` + `-f` flags for each compose file (resolved relative to `root_dir`) + `--profile` flags for each profile + the args.

**Method `start(self) -> None`:**
1. Call `_cleanup_orphans()`
2. Call `_compose_up()`
3. Call `_wait_for_readiness()`
4. Set `_started = True`
5. Call `_register_cleanup_handlers()`

**Method `stop(self, capture_logs: bool = True) -> None`:**
- If `_cleaned_up` is True, return immediately (idempotent -- Pitfall 3)
- Set `_cleaned_up = True`
- If `capture_logs and self._started`, call `_capture_logs()` (stub that passes for now -- Plan 02 implements it)
- Call `_compose_down()`
- Call `_restore_signal_handlers()`

**Method `_cleanup_orphans(self) -> None`:**
- Run `docker compose ls --format json -a`, parse JSON output
- For each project whose Name starts with `PROJECT_PREFIX` AND is not equal to `self._project_name`, run `docker compose -p {name} down -v -t 10`
- Log each orphan removed: `print(f"[container_manager] Removing orphaned project: {name}")`
- Handle subprocess errors and JSON parse errors gracefully (warn and continue)

**Method `_compose_up(self) -> None`:**
- Run `self._compose_cmd("up", "-d", "--wait", "--wait-timeout", "120")`
- Use `subprocess.run(cmd, capture_output=True, text=True, timeout=180)`
- If returncode != 0, raise RuntimeError with stderr
- Print status messages

**Method `_wait_for_readiness(self) -> None`:**
- DB readiness is handled by `docker compose up --wait` (compose healthchecks)
- For httpd: run `self._compose_cmd("exec", "-T", "rucio", "curl", "--retry", "15", "--retry-all-errors", "--retry-delay", "2", "-k", "-s", "-o", "/dev/null", "-w", "%{http_code}", "https://localhost/ping")` with timeout=60
- If returncode != 0, raise RuntimeError
- Print readiness status

**Method `_compose_down(self) -> None`:**
- Run `self._compose_cmd("down", "-v", "-t", "30")`
- Use `subprocess.run(cmd, capture_output=True, text=True, timeout=120)`
- Log result, do NOT raise on failure (cleanup should be best-effort)

**Method `_capture_logs(self) -> None`:**
- Stub implementation: `pass` (Plan 02 will implement full log capture)

**Method `_register_cleanup_handlers(self) -> None`:**
- Save original signal handlers: `self._original_sigterm = signal.getsignal(signal.SIGTERM)`, same for SIGINT
- Register atexit handler: `atexit.register(self.stop, capture_logs=False)`
- Define `_signal_handler(signum, frame)` that:
  1. Calls `self.stop(capture_logs=True)`
  2. Restores the original handler for the given signal
  3. Re-raises the signal so the process exits with correct status (see Pitfall 4: use `start_new_session=True` on cleanup subprocesses to avoid SIGINT propagation)
- Register for both SIGTERM and SIGINT

**Method `_restore_signal_handlers(self) -> None`:**
- Restore original handlers if saved, set saved values to None

**Static method `make_project_name(suite_name: str, rdbms: str) -> str`:**
- Returns `f"rucio-test-{suite_name}-{rdbms}"` (SUIT-05)

Add Rucio Apache 2.0 license header. Add module docstring explaining host-side operation.

  <name>Task 2: Wire ContainerManager into plugin.py pytest_configure and add pytest_unconfigure hook</name>
  <files>tests/ruciopytest/plugin.py</files>
  <action>
Modify `tests/ruciopytest/plugin.py` to integrate ContainerManager.

**Add a new stash key:**
```python
container_manager_key = pytest.StashKey["ContainerManager"]()
```
Use a string type annotation to avoid import-time dependency on ContainerManager.

**In `pytest_configure`, inside the `if not is_worker:` block, BEFORE the InfraManager setup:**

1. Check if running inside a container: `if os.path.exists("/.dockerenv") or os.environ.get("RUCIO_SOURCE_DIR"):` -- if yes, skip container lifecycle (print message and proceed to InfraManager)
2. If NOT inside a container AND `profile.compose_profiles` is not empty (skip for client suite which has empty compose_profiles or suites that don't need containers):
   - `from .container_manager import ContainerManager` (lazy import, same pattern as InfraManager)
   - `project_name = ContainerManager.make_project_name(profile.name, profile.rdbms)`
   - `cm = ContainerManager(project_name, profile.compose_profiles, str(config.rootdir))`
   - `cm.start()`
   - `config.stash[container_manager_key] = cm`

The InfraManager setup block stays AFTER container start (DB must be running before InfraManager purges/builds it).

**Add `pytest_unconfigure(config)` hook:**
```python
def pytest_unconfigure(config: pytest.Config) -> None:
    """Stop containers on session end."""
    cm = config.stash.get(container_manager_key, None)
    if cm is not None:
        cm.stop(capture_logs=True)
```

**Ordering note:** The container start must happen BEFORE InfraManager.setup() because InfraManager needs the database container to be running. The existing code has InfraManager in the `if profile.name != "client":` block. The container start should wrap around it, inside the same `if not is_worker:` block.
