  <files>tests/ruciopytest/container_manager.py</files>
  <action>
Replace the `_capture_logs` stub in ContainerManager with full implementation. Follow the locked decision: capture ALL compose services, full log history, output to `.test-logs/` directory.

**Method `_capture_logs(self) -> None`:**

1. Create log directory: `log_dir = Path(self._root_dir) / self.LOG_DIR` and `log_dir.mkdir(parents=True, exist_ok=True)`

2. Capture combined log from all services:
   - Run `self._compose_cmd("logs", "--no-color", "--timestamps")`
   - Write stdout to `log_dir / f"{self._project_name}.log"`
   - Print path: `print(f"[container_manager] Combined logs saved to {combined_log}")`

3. Capture per-service logs:
   - First get service list: `self._compose_cmd("config", "--services")` with timeout=10
   - For each service name in stdout (split by newline, strip empty):
     - Run `self._compose_cmd("logs", "--no-color", "--timestamps", service)` with timeout=30
     - If stdout is non-empty, write to `log_dir / f"{service}.log"`
   - Print: `print(f"[container_manager] Per-service logs saved to {log_dir}")`

4. All subprocess calls should use `capture_output=True, text=True` with reasonable timeouts (30s per service)

5. Handle errors gracefully: if any log capture fails, print warning but do NOT raise (log capture must never prevent cleanup)

Also add a **property** `log_dir -> Path` that returns `Path(self._root_dir) / self.LOG_DIR` so plugin.py can access it for the terminal summary without knowing the internal constant.

  </verify>

  <action>
Add a `pytest_terminal_summary` hook to plugin.py that prints container log file locations and optionally adds them to JUnit XML.

**Add the hook function:**
```python
def pytest_terminal_summary(terminalreporter, exitstatus, config):
    """Print container log file locations and add to JUnit XML."""
    cm = config.stash.get(container_manager_key, None)
    if cm is None:
        return

    log_dir = cm.log_dir
    if not log_dir.exists():
        return

    log_files = sorted(log_dir.glob("*.log"))
    if not log_files:
        return

    # Print log file locations in terminal
    terminalreporter.write_sep("=", "Container Logs")
    for log_file in log_files:
        terminalreporter.write_line(f"  {log_file}", yellow=True)
    terminalreporter.write_sep("=")

    # Add to JUnit XML if --junitxml was specified
    xml_plugin = config.pluginmanager.get_plugin("junitxml")
    if xml_plugin is not None:
        # The junitxml plugin stores the LogXML instance; access it to add global properties
        # pytest stores the LogXML reporter; we can add global properties via it
        try:
            for log_file in log_files:
                xml_plugin.add_global_property(
                    f"container_log:{log_file.name}",
                    str(log_file)
                )
        except (AttributeError, TypeError):
            # Fallback: junitxml API may vary across pytest versions
            pass
```

**Important details:**
- Use `terminalreporter.write_line(..., yellow=True)` for visibility (log paths stand out in yellow)
- The `xml_plugin` from `config.pluginmanager.get_plugin("junitxml")` returns the LogXML instance which has `add_global_property()` in pytest 7.4
- If junitxml plugin is not active (no --junitxml flag), skip XML integration silently
- The hook runs BEFORE pytest_unconfigure, so containers are still up and log_dir exists
