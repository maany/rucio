<task type="auto">
  <name>Task 2: Create simple-autotest.yml workflow</name>
  <files>.github/workflows/simple-autotest.yml</files>
  <action>
Replace the existing prototype simple-autotest.yml entirely with a clean workflow:

**Workflow name:** "Simple Autotests"
**Triggers:** pull_request (same as the old autotest.yml would have)
**Concurrency:** group by workflow + ref, cancel-in-progress: true

**Jobs:**

1. `runtime_images` job:
   - `uses: ./.github/workflows/runtime_images.yml`
   - `permissions: { packages: write }`

2. `test` job:
   - `needs: [runtime_images]`
   - `runs-on: ubuntu-latest`
   - `permissions: { checks: write, contents: read }` (needed for mikepenz/action-junit-report)
   - `strategy.fail-fast: false`
   - `matrix.include` with 6 entries per user decision:
     ```
     - suite: remote_dbs, python: "3.9", rdbms: postgres14
     - suite: remote_dbs, python: "3.10", rdbms: postgres14
     - suite: sqlite, python: "3.9", rdbms: sqlite
     - suite: multi_vo, python: "3.9", rdbms: postgres14
     - suite: client, python: "3.9", rdbms: postgres14
     - suite: votest, python: "3.9", rdbms: postgres14
     ```

   **Steps:**
   a. `actions/checkout@v5` (use commit hash from autotest.yml: `93cb6efe18208431cddfb8368fd83d5badbf9bfd`)
   b. `docker/login-action@v3` (GHCR login, same pattern as autotest.yml, with `continue-on-error: true`)
   c. `docker/setup-buildx-action@v3` -- only needed for local build fallback
   d. Local image build step (conditional: `if: needs.runtime_images.outputs.build_locally == 'true'`):
      - Uses `docker/build-push-action@v6`
      - file: `etc/docker/test/runtime.Dockerfile`
      - target: final
      - build-args: `PYTHON=${{ matrix.python }}`
      - push: false
      - tags: select py39 or py310 image based on matrix.python
      - outputs: `type=docker`
      - cache-from: `type=registry,ref=ghcr.io/${{ steps.repo.outputs.repo }}/rucio-dev-runtime:py${{ steps.pynodot.outputs.pynodot }}-buildcache`
      - Add a step before this to compute `repo` (lowercase github.repository) and `pynodot` (python version without dot)
   e. Run tests:
      ```yaml
      - name: Run tests
        env:
          RUCIO_TEST_IMAGE: ${{ matrix.python == '3.10' && needs.runtime_images.outputs.py310_image || needs.runtime_images.outputs.py39_image }}
          RDBMS: ${{ matrix.rdbms }}
          PYTHON: ${{ matrix.python }}
        run: |
          python -m pytest \
            --suite=${{ matrix.suite }} \
            --junitxml=test-results/${{ matrix.suite }}-py${{ matrix.python }}.xml \
            -r fExX \
            --log-level=DEBUG \
            -v --tb=short \
            tests/
      ```
   f. Upload JUnit XML (always):
      ```yaml
      - name: Upload test results
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: test-results-${{ matrix.suite }}-py${{ matrix.python }}
          path: test-results/
          if-no-files-found: ignore
      ```
   g. Upload container logs (failure only):
      ```yaml
      - name: Upload container logs
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: container-logs-${{ matrix.suite }}-py${{ matrix.python }}
          path: .test-logs/
          retention-days: 7
          if-no-files-found: ignore
      ```
   h. Publish test report (always):
      ```yaml
      - name: Publish test report
        if: always()
        uses: mikepenz/action-junit-report@v6
        with:
          report_paths: test-results/*.xml
          check_name: Tests - ${{ matrix.suite }} (py${{ matrix.python }})
          fail_on_failure: true
      ```

**CRITICAL anti-patterns to avoid:**
- NO docker compose up/down/exec steps (plugin handles this)
- NO alma9.Dockerfile references (use runtime.Dockerfile via runtime_images.yml)
- NO local buildx cache (actions/cache) -- use GHCR registry caching via runtime_images.yml
- NO readiness wait steps (plugin's ContainerManager does this)
- NO shell script orchestration
